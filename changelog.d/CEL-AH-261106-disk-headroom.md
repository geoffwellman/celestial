### Added
- A supported recurring 20 GiB disk-headroom controller reuses reviewed SHA-pinned release, ordinary and preservation handlers, stops at the available-space target, and records durable producer blockers and any remaining byte deficit. Safe Docker cleanup requires explicit opt-in, safety-v1 capability and a reviewed CLI/runtime snapshot shared by capability lookup and mutation; no global prune or inferred producer grants.
- Transactional installation preserves standalone scripts and timers, refuses active units and later `ExecStart` overrides, saves independent durable preimages, and rolls back file/reload failures. Migrated disk services share one controller lock; expected overlap exits 75 without claiming recovery. Separate steward cache sweeps are not globally serialized.
- Handler dispatch reserves diagnostic/notification time; failed, skipped or timed-out cleanup defers routine root capacity decisions while retaining explicit emergency escalation. Notification debt honors its retry time and confirmed enqueue acknowledgment. Documentation and isolated real-child tests cover thresholds, budget boundaries, adapter drift, frozen CLI execution, retry/dedupe and install rollback. No live migration or cleanup occurs during build/test. See `docs/disk-headroom.md` for parent-controlled deployment and rollback.
- CLI subprocesses explicitly bind `CEL_ROOT` to their vetted snapshot/deployment rather than inheriting another tree. Documentation makes Docker opt-out's lane-only normal-capacity behavior explicit; hostile-root regression tests cover capability, sweep and notification calls.
