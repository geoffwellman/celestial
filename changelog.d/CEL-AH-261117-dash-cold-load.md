### Fixed
- The dashboard's first load after a restart no longer waits on its slow feeds (gh PR lists, merged-PR counts, `cel quota`, `cel solo approvals`): it took 7-10 s, over a minute on a cold box. Each good build of the page's snapshot (per ws filter) and of `/api/state` (per workspace) is saved privately (0700 directory, 0600 files, written atomically) under the dash state dir, and a cold start answers both at once from that file - the snapshot marked `stale: true` with `as_of`; `/api/state` marked `saved: true` with `as_of`, because its `stale` field already lists stale worktrees - while the live build runs behind it. With nothing saved, the first answer carries the fast parts (the roster, decisions, inbox, load, teams) and names the rest in `loading`. The page shows "updating, as of HH:MM" and swaps in each live answer as it lands. The per-browser "Since you last looked" card is never saved (a stale answer says it is loading), a saved snapshot is served only for a workspace still in the registry, a build made while an upstream read failed never replaces a saved one built with fewer failing, and the file is only ever served to a cold start's first ask - never after an action, and never to the actions themselves.
- One dashboard request the server never answered froze the page's refresh for good; every read now has a deadline (three refreshes, at most a minute), and a refresh round that has not settled is replaced.
