### Added
- `cel run reviewer --repo r --pr n --focus <f>` starts an extra reviewer for the PR beside its plain one: the focus pack `core/roles/focus/reviewer/<f>.md` appended to the reviewer role, its own alias (`<repo>-pr-<n>-review-<focus>`), pane, checkout (`<reviews>/<repo>-pr-<n>-review-<focus>`), mailbox and registry row, admitted against the box helper budget like any reviewer. An unknown focus is refused naming the packs there are; a focus whose 32-character alias would be another reviewer's is refused.
- `review.extra` in workspace.yaml (workspace-wide, and under a `repos[]` entry): entries of `focus`, `paths` (globs: `*`/`?` within one directory level, `**` as a whole segment across any number of directories, whole-path match) and `kind` (`review`, the default and only kind). `cel run reviewer --repo r --pr n` starts the plain reviewer and every extra one whose paths match a file the PR touches, saying which and why. It is read from workspace.yaml only; workspace.local.yaml cannot add or drop one. Nothing malformed is skipped: a bad entry, a `review:` that is not a map or has a key Celestial does not know (workspace-wide runtime/model/extra and the retired post, per repo extra - `extras:` is an error), or two `repos:` entries of one name refuse the policy read, and `cel doctor` reports each.
- `cel solo review ... --focus <f>` records an extra reviewer's verdict under `<repo>#<n>/review-<focus>` in `.cel/solo-reviews.json`, only from a caller launched as that reviewer (`CEL_ROLE=reviewer`, `CEL_INBOX_ME` its alias). A caller launched as a reviewer must give `--by` equal to its own mailbox on the plain slot too. On Herdr this is the launch environment (the author guard's trust); Rex reviewers are bound by `cel_assert_reviewer_identity`.
- `cel solo approvals <repo>#<n>... [--json]`: each reviewer a PR needs and its word on the current head, by land's rule.
- `forge_pr_files` (lib/forge.sh): every path a PR touches, both sides of a rename, on GitHub and Forgejo; a GitHub list at its 3000-file cap is refused.

### Changed
- `cel solo land` requires an approval of the exact current head from every reviewer the review policy requires for that PR (the plain one and each matching extra one, computed from the PR's files at land time), counted only from a verdict that reviewer's own alias recorded; the refusal names each missing or stale reviewer and the command that starts it, or, for one whose cut alias collides so it can never start, what to change. A focus reviewer started by hand that the policy does not require is advisory, except that its `changes` at the head being merged blocks the land. Every existing land check is kept.
- The steward's "approved and green, land it" nudge (`solo_ready_prs`) and dashboard v2's PR approval (via `cel solo approvals`) use the same rule; the PR card names the required reviewers still owed.
- `cel gc`, the reviewer registry, `reviewers_discover`, the budget classifier, the gateway-rotation plan, dashboard identities and Rex reviewer retirement know extra reviewers: each is closed or retired on its own verdict, and the land retires the PR's extra Rex reviewers too.
- The rendered workspace policy names the extra reviewers when `review.extra` declares any.
