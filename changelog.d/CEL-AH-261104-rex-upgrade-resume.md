### Added
- Rex receipts for core, root, orchestrators and solo lanes record the canonical `cel run` line that brings the agent back (role, product, lane, workspace, `--session-backend rex` and only the profile/model/thinking you named; a lane keeps its remembered choices).
- The steward detects a Rex server restart (a changed server instance) and resumes, once, every managed Rex agent that was live under the old server and was not stopped, retired or relaunched since, through its recorded line, into its saved session, then confirms it is alive and sends root one summary (and each resumed agent a note that its background work ended). Reviewers, workers, agents with no saved session and receipts from before this change are listed instead, with the command to run.
- Before those resumes it repairs the restarted server: it closes the empty restored duplicate sessions of the agents being resumed (never a session still running a program), starts a persistent server if closing them ended an `--exit-empty` autostarted one, turns tailnet serving back on and verifies it when the old server served the tailnet, and reports the server's version and API revision before and after.
- Managed rex upgrades: `cel sessions rex-upgrade [--check]`, and a steward step every 30 minutes. When apt offers a newer rex from `pkgs.superlogical.com`, it waits (bounded) for every live Rex agent to be idle and resumable - otherwise it skips the round - records them and the server's tailnet state, runs `sudo -n apt-get install --only-upgrade -y rex`, restarts the per-user Rex server (persistent, in its own systemd scope) if the package did not, then restores and resumes as above and sends root one summary.
