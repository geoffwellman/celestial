### Added
- Rex receipts for core, root, orchestrators and solo lanes record the canonical `cel run` line that brings the agent back (role, product, lane, workspace, `--session-backend rex` and only the profile/model/thinking you named; a lane keeps its remembered choices).
- The steward detects a Rex server restart (a changed server instance) and resumes, once, every managed Rex agent that was live under the old server and was not stopped, retired or relaunched since, through its recorded line, into its saved session, then confirms it is alive and sends root one summary (and each resumed agent a note that its background work ended). Nothing is resumed when the new generation cannot be recorded. Reviewers, workers, agents with no saved session and receipts from before this change are listed instead, with the command to run.
- Before those resumes it repairs the restarted server: it closes the empty restored duplicate sessions of the agents being resumed (only sessions whose every block reports child and foreground as null; anything else is kept), starts a persistent server if closing them ended an `--exit-empty` autostarted one, turns tailnet serving back on and verifies it when the old server served the tailnet, and reports the server's version and API revision before and after.
- Managed rex upgrades: `cel sessions rex-upgrade [--check]`, and a steward step every 30 minutes. When apt's candidate is newer and comes from exactly `https://pkgs.superlogical.com`, it waits (bounded) for every live Rex agent to be idle and resumable, and refuses while the server holds any session that is not a live managed launch - otherwise it skips the round - then records them and the server's tailnet state, installs exactly that version (`rex=<version>`), restarts the per-user Rex server (persistent, in its own systemd scope) if the package did not, restores and resumes as above, and sends root one summary.

### Fixed
- Reviewer retirement no longer fails when the native side's answer replaces the previous one while it is being read (seen as `evidence_changed_during_read` and an intermittent CI failure); a reviewer process reaped between opening and reading its `/proc` stat counts as exited; an unexpected retirement error now reports its cause.
