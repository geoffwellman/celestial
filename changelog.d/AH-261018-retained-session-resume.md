### Fixed
- `cel-fanout delegate --reuse` (and `handback`, which resumes through it) over a gc-retired row now resumes the SAME worker: the row's recorded runtime, model, thinking and profile (not the workspace's current role default, which had silently turned resumed Sonnet workers into the DeepSeek default) and the original native session (`--session <file>` for pi; `--resume` for runtimes that declare it). The session is the one recorded on the row, else - for pi - the single session file whose header names the worktree; zero, several (disambiguate with `--session <uuid>`), or a header for another cwd is refused. Everything is proved before any pane command or ledger write, and refused with zero mutation: an unsettled launch, a non-retained state, a worktree the row does not own, a live agent for the alias or in the worktree (no live runtime is ever stopped), `--profile/--model/--thinking` contradicting the row, a profile whose definition drifted from the row, a runtime with no native resume. Normal fresh admission (worker cap, box memory) still applies.
- The resumed row is the same row: spec, review verdict/head, PR, profile reason and `history` are kept and the resume is one more recorded transition; the new pane, alias and `session` are recorded. Previously `--reuse` replaced the row (dropping history) and `handback` patched it back afterwards.
- Not a live-retirement API: that remains the unimplemented scope of PR176.
- Real-shape session checks: the resumed session's LATEST native model is the later of its last `model_change` and last assistant message's own model (a session can switch model with no `model_change`), its thinking is the last `thinking_level_change`; either disagreeing with the row is refused, never resolved by picking one. The session is named by its HEADER uuid (the file name is irrelevant), and a process already holding the file refuses the resume.
- **Unsupported, fails closed:** resuming a RECOVERED or PRIVATE-ROOT session (a session file outside the default pi session root, or `--receipt`) is refused with zero mutation. No default-root, fresh-conversation or path fallback is substituted, and preserving a private root / re-pinning a row from a recovery receipt is not implemented.
- A retained row whose checkout no herdr workspace holds any more (its workspace/pane was closed - the AMPDGC shape) is no longer refused with a suggestion to `worktree remove --force`: after every proof has passed, the existing checkout is opened with `herdr worktree open --path <checkout> --branch <branch> --no-focus` (never removed, never recreated) and resumed in. A refusal opens nothing.
- `cel-fanout delegate` no longer exits 141 (silently) on a spec that quotes more than a pipe buffer (64 KiB) of finding while AFK is on: the AFK dispatch gate took the first `Finding-from:`/`> ` line with `sed ... | head -1`, and under `set -o pipefail` the early-exiting `head` SIGPIPEd `sed`. sed now stops itself (`{p;q}`); `_ledger_entry` and `_container_id` use jq `first()` instead of `| head -1` for the same reason (hardening, not reproduced at VHS ledger sizes).
