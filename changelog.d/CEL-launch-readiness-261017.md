### Fixed
- `cel run` no longer types the launch line (role environment and gateway credential substitution) into a pane whose shell is not ready. It waits, bounded by `CEL_PANE_READY_MS` (default 30000), until herdr's `pane get`/`pane process-info` show the same terminal and shell, no agent, and the shell alone in the foreground (its process group included) for `CEL_PANE_READY_STABLE` (3) consecutive probes; on timeout, an occupied pane, an unreadable pane or a changed owner it fails before anything is typed - no `agent start`, no reviewer record. A pane that changes after the line was typed is refused, and `herdr agent start` is tried once: a refusal after typing reports the pane and that an unsubmitted line (contents withheld) is pending, with no retry, Enter or key sent. Covers console, root, orchestrator, worker, reviewer and `--restart`. It waits for the shell state `herdr agent start` itself requires; the root cause of a downstream workspace's `agent_pane_busy` reviewer launches is unproven (timing is a hypothesis), and herdr 0.9.1 exposes no structured prompt-drawn field, so 3 stable probes is a mitigation, not proof the prompt is drawn (upstream prerequisite). Also covers `cel-fanout delegate`. Installed sessions keep the old CLI until this is deployed.
