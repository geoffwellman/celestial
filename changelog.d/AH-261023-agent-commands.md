### Added
- In-agent commands for core, orchestrators and solo agents: `/cel-mode [product] [solo|fleet]`, `/cel-status [product]`, `/cel-inbox`, `/cel-decide`, `/cel-review [repo#]<pr>`, `/cel-land [repo#]<pr> [flags]`, `/cel-restart`, and in core `/cel-focus <product>`. Each runs `cel here <verb>` (new, `lib/here.sh`), a thin wrapper over one `cel` command scoped to the pane's own product (from its launch identity) unless a product is named; core names one as `<product>` or `<workspace>/<product>`, reads root's mail and every decision, and is refused review and land. `/cel-land` takes the mode's checked path: `cel solo land`, or `cel-fanout land <id>` on the delegation whose branch is the PR's head. `/cel-restart` schedules the same end-of-turn waiter `cel mode` uses (core gets its own), never an inline restart. The omp/pi inbox extension registers them for core, root, orchestrator and solo panes only and posts their output into the conversation without starting a turn; Claude Code gets `~/.claude/commands/cel-*.md` links from `cel setup`/`cel update` (stale plane links are pruned). Prefixed `cel-` because omp has built-in `/review` and `/restart` and Claude Code built-in `/status` and `/review`.
- A product agent's `/cel-*` act on its own product only (naming a sibling is refused - that is core's job); core's restart waiter runs only as core; the worker guard refuses `cel here`.
- `cel decide list --workspace <w> --asker <alias>` narrows the list to one workspace and/or one asker.

### Changed
- `cel mode`'s detached restart is split into reusable pieces (`_mode_detach`, `_mode_when_quiet`); behaviour is unchanged.
