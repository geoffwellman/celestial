### Added
- QA agents on UI PRs. `review.extra` entries take `kind: qa` (`{kind: qa, focus: browser, paths: ['web/**', '**/*.tsx', '**/*.css']}`): a PR touching those paths needs a QA agent's approval of its exact head to land. The focus packs are `core/roles/focus/qa/` (`browser`, `exploratory`, `mobile-device`), the ones feature-team qa members use.
- `core/roles/pr-qa.md`: the QA agent does not read the code, it uses the change. It builds and runs the head with `cel preview <repo>#<n> --qa <focus> --head <sha>`, drives it in a real browser (or a device or simulator), walks what the PR claims plus edges, and records `cel solo review <repo>#<n> approved|changes|blocked --head <sha> --by <alias> --qa <focus> --evidence <file>... --note "..."`.
- `cel run reviewer --repo r --pr n` starts the matching QA agents beside the plain reviewer (same budget admission), and `cel run reviewer --repo r --pr n --qa <focus>` starts one by hand. Alias `<repo>-pr-<n>-qa-<focus>`, checkout `<reviews>/<repo>-pr-<n>-qa-<focus>`, verdict key `<repo>#<n>/qa-<focus>`, registry row with `kind: qa`; no name collides with a `review-<focus>` extra.
- `blocked` verdict (QA agents only, `--note` required): the agent could not run the change. `cel solo land` treats it as not approved and names the agent, the reason and its start command. `approved` and `changes` need at least one `--evidence` file named with the head's first 12 characters, copied to `.cel/qa-evidence/<repo>-pr-<n>/qa-<focus>/` and listed in the verdict.
- `cel preview --qa <focus>` gives a QA agent its own preview (`preview-<repo>-pr<n>-qa-<focus>`) beside any plain one. `cel preview --head <sha>` refuses any other head.
- `role_profiles.qa` picks a QA agent's model, falling back to `role_profiles.reviewer`, then `review.model`. `cel profiles` lists it.
- `cel sessions retire-reviewer <repo>#<pr> --focus f | --qa f` targets an extra reviewer or QA agent.

### Changed
- Every `CEL_ROLE=reviewer` (plain, `--focus`, `--qa`) is judged by that launch role wherever it stands, against allowlists: git read verbs after any global options (`-c` refused; `fetch` only without a refspec colon, `+` or `--force`), cel `solo review|approvals`, `inbox`, `preview`, `serve list|start|stop`, forge reads, `fleet`, `status`, `profiles`, `budget`, `people`, `decide|learn list`, `help`, and gh reads plus `gh pr comment` / `gh pr review --comment`. Everything else (pushes, `pull`, `update-ref`, `branch`, `config`, merges by any tool, `cel solo land`, `cel afk|release|update|learn add|mode|decide ask|ws|team|run|gc`, agent and pane starts) is refused, with no `CEL_GUARD_ALLOW_ONCE` override.
- Retiring a QA agent stops its preview and removes that preview's checkout and its own checkout: `cel gc` (finished, PR closed, pane gone, Herdr or Rex) and `cel solo land` through `reviewer_checkout_release` and `reviewer_retire_target`. A finished QA agent's checkout is removed, where a reviewer's is kept. A preview server that will not stop keeps its record and the retirement warns; the steward's `preview_sweep` stops a QA preview once no live agent bears its owner's name.
- A QA agent's `approved` or `changes` needs its own preview of that head on record when recorded; evidence must be a regular, non-empty file (no symlink), the image its name says, and is copied with its sha256 and size.
- QA previews run with a private, empty `HOME` under their own state directory.
- `cel solo land`, `solo_ready_prs` (the steward's nudge), `cel solo approvals` and the dashboard read QA agents through the same `solo_extra_approvals` rule. A hand-started QA agent the policy does not require is advisory, and its `changes` at the head blocks. `cel solo approvals --json` reviewers carry `kind`.

### Fixed
- Rex retirement proof (`tools/reviewers/retire.mjs`, `tools/hooks/reviewer-retirement.mjs`) accepts an extra reviewer's `<focus>.role-reviewer.md` and a QA agent's `qa-<focus>.role-reviewer.md`, so those Rex agents can be retired too.
