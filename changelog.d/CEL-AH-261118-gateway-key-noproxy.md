### Fixed
- The gateway api-key never goes to a proxy. curl uses `http_proxy`/`HTTPS_PROXY`/`ALL_PROXY` even for `127.0.0.1`, so a proxy could have been sent the key that spends every subscription behind the gateway. The following requests now go through `curl_direct` (`lib/common.sh`): every `/v1/models` read that carries the key (`_gateway_models_json_raw`, `gateway_models_json_existing` and the read-only OpenCode catalog read), `cel gateway rotate-key`'s key probe, and a service health check that sends a bearer to a loopback URL. `curl_direct` passes `--disable` as its first argument, so a `~/.curlrc` cannot add a proxy or a header, then `--noproxy '*'`, and it runs curl with every proxy variable removed. The gateway management requests already used it. The loopback-URL check is now shared as `url_is_loopback` in `lib/common.sh`.
