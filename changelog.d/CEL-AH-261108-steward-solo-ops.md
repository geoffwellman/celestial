### Fixed
- The steward's PR review sweep no longer sends fleet remedies to a solo product. A red or changes-requested PR in a `mode: solo` product goes to that product's agent as a fix-it-on-the-branch finding ("fix it on the branch and push", "ask its reviewer to re-review"), without looking up delegation rows or worker panes on the branch and without "get a worker" or "restart the worker" wording.
- Every rewrite of the steward's shared state (nudge rate limits, first-seen records, forgets, restart claims, the freed-bytes total and service down-counts) now goes through one locked edit that publishes a unique temp file by rename. Two ticks, or a tick beside a hand-run helper, no longer drop each other's keys, and a fixed `.tmp` name can no longer be clobbered or left half-written.
- `cel update --rollback` drops each rolled-back agent from its record under the same lock and temp-file-plus-rename as recording does, so an interrupted rollback can no longer truncate the record and an entry recorded while it runs is no longer lost.
- `cel doctor` reports a repository checkout as behind only when it is on its default branch, and its remedy now names the remote and branch it counted against (`git -C <dir> pull --ff-only origin <branch>`). A checkout on a feature branch or a detached head is not reported, and is not fetched.
- The daily unledgered-server report is stamped per product, and only once delivery to that product succeeded; a product whose inbox send failed is tried again on the next tick instead of waiting for the next day.

### Changed
- The steward runs `cel-fanout reconcile` and the stalled-worker sweep only for a workspace whose delegation ledger still has a row that is not landed, released or abandoned (an unknown state or an unreadable ledger counts as live). When a ledger has nothing live, any stall items still open for it are taken down.
- `cel doctor` summarises preview servers as one count line pointing at `cel serve list` (and `cel serve adopt` for unledgered ones) instead of listing every server.
