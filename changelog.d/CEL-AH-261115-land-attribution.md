### Changed
- `cel solo land` now records which agent landed a PR. The forge shows every land as merged by the workspace's account (the owner's token), so the squash message now ends in git trailers: `Reviewed-by:` for the recorded verdict's reviewer, each approving forge account and each required extra reviewer, then `Landed-by: <agent alias> (cel solo land)`, then the existing `Gate:` line. The review note, if any, moves to its own paragraph above the trailers.
- Just before the merge, `cel solo land` comments on the PR: `Landing as <alias> via cel solo land (attempting): approved by <reviewer> at <sha>, checks green.` If the forge refuses the merge, a second comment says `Not landed: ...` and gives the forge's reason. If a comment is refused, the land reports it and the merge still goes ahead. This works on both GitHub and Forgejo.
- The lander is named by the alias from its launch only when it is a solo or orchestrator agent. A shell with no role is recorded as the forge account, `by hand`; any other role is recorded as `an unnamed agent`.
- Every name in the record must be a single token. A name carrying a control character stops the land before anything is posted, so a newline in a name cannot add a fake trailer.
- New forge operation: `forge_pr_comment`.
