### Fixed
- `cel inbox watch --parent` no longer leaves a watcher behind when its agent dies. The parent used to be followed by a subshell that forked `sleep` every five seconds; a transient fork failure killed that subshell silently (bash gives up after its retries without sending the group kill), the rest of the watcher lived on with nothing following the agent, and when the agent later died the watcher was reparented to init until the steward reaped it ("reaped 1 orphan (1 watcher), 3 MB"). The parent is now followed by the watcher's own `tail --pid` (GNU and uutils coreutils), which never forks, so any element dying ends the whole watch; a tail without `--pid` is detected and the watch shell follows the parent itself instead. Both poll every five seconds, as before. Reviewer retirement accepts both shapes.
- The steward's orphan reap report goes to the first registered workspace's root mailbox only (the box is one box), and only when the reap differs from the last one reported: it now carries the reaped classes but not the megabytes, which the journal line still shows.
- A steward "<agent> will not start" alert is no longer raised while an open `cel decide` card covers it - a card in the same workspace whose title or blocks names the agent as a name of its own, or names the product directly followed by "orch", "orchestrator" or "solo agent" (names matched literally, never as patterns; a longer hyphenated name or another agent of the product does not match). An alert raised before the card was filed is taken down naming the card, and it comes back if the card closes while the launch still fails. Otherwise the alert is raised once per change instead of on every half-hourly retry.
- An OpenCode guarded private launch that refuses now says why: `OpenCode guarded private launch refused (reason=<code>)`, with a fixed, non-secret code per refusal step (for example `server_exited`, `server_not_ready`, `plugin_request_timeout`, `guard_inactive`, `migration_incomplete`, `session_identity`, `model_unscoped`). Native and config error text is still never printed.
