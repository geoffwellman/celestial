### Fixed
- The dead-mise-shim check (#341) had no time limit, so a hung `mise` could hang `cel doctor`, `cel setup`, `cel update` or `cel run`. Its `mise which` and its fallback `<shim> --version` now each run under `timeout -k 1 5` (`CEL_SHIM_CHECK_SECS` overrides the 5). A timeout (exit 124) or a kill (exit 137: past the grace period, or out of memory, reported as "killed (timed out after Ns, or out of memory)") means "cannot tell", never "dead":
  - `cel run` warns and launches.
  - `cel setup` warns and retains the agent.
  - `cel update` skips that agent's updater, whose version read and updater would only hang in the same mise. It reports `<agent> NOT updated` and exits non-zero.
  - `cel doctor` warns and says how many shims went unchecked (`N of M mise shims not checked`). It keeps checking the rest.
  - When `mise which` itself times out in a directory, later checks from that directory in the same command answer straight away. That record is a per-command file, so it holds across `$(...)` subshells. Other directories are still asked. A single shim whose `--version` hangs is that shim's "cannot tell" only.
- `cel doctor`, `cel setup` and `cel update` ran the shim check from whatever directory they were started in, so a project's own mise config decided the answer. They now ask in the global mise context (`$HOME`). That is the node agents get unless a workspace's own mise config selects another, and it is where a reinstall's `npm install -g` now writes. Doctor's dead-shim message says it was checked there.
- `cel run` still asks from the launch's own directory. When only that directory's mise config selects a node without the agent, the refusal now says so. It names the directory and its node, notes that `cel setup` and `cel update` repair only the global node (so they would change nothing there), and gives the install that works in that directory, for example `cd <dir> && npm install -g --ignore-scripts "@earendil-works/pi-coding-agent@1.5.0"`.
