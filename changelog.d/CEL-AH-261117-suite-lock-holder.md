### Fixed
- The steward's "suite lock held" alert names whose run it is. `tests/run.sh` now writes a private holder record beside the suite lock (pid and its kernel start time, the caller's `CEL_INBOX_ME`/`CEL_INBOX_WS`, the checkout's top level, the files asked for, the start time), written whole and removed when the run exits. The alert names the agent, worktree, what it is running and for how long, and goes to that agent's mailbox in its workspace plus one line to root of the box's first workspace, instead of to root in every workspace. With no record - or one whose pid and start time do not match the current holder, as when a killed run's pid is reused - it keeps the old wording and goes to root once. The `cleared:` line goes to the same recipients.
