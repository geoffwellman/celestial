### Fixed
- The steward's unledgered-server report no longer sends a repo's dev servers to root as "outside every workspace" when they run in a non-git dir beside the repo's checkout. A dir no git identity places is now the owner's of the repo whose real root (`repos/<repo>` with symlinks resolved) it is under or whose `<real root>-` it starts with - `~/code/<repo>-local-cf-data`, `~/code/<repo>-wt`, release dirs next to `~/code/<repo>` - the longest root winning. Worktrees of a symlinked repo were already routed to its owner by git identity, wherever they live; that is now covered by tests.
- Root's summary of new unledgered servers says, after each one routed to another agent, who was told (`, told <mailbox> (<workspace>)`), so a server routed to its owner no longer reads as root's own. A server in no workspace is reported to root of the box's first workspace in registry order, and the summary names that workspace whether the box has one workspace or several.

### Added
- `repos[].owns_paths: [<glob>, ...]` in the committed `workspace.yaml` claims other dirs for a repo's owner in that report and in the idle build-daemon note (`~/` is the home dir, a relative glob is under the workspace, a dir under a match matches, the longest glob wins). It decides after git identity and before the real-root prefix rule; `workspace.local.yaml` cannot add one.
