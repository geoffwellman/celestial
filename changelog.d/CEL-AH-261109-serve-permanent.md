### Added
- `cel serve adopt <unit|pid> --owner <alias> --workspace <ws> --permanent [--port N] [--why "..."]` registers an agent's standing box service (a product's live app in a persistent user unit, a preview its owner said to keep) as a permanent server: no TTL, no idle or pressure limit. The steward's `serve_sweep` never stops it, `preview_sweep` skips it quietly, gc's QA-preview release (through `_preview_teardown`) refuses it, the orphan reaper never lists its pid (while the pid's start time is the recorded one) or any process in its unit, and the unledgered report skips it. `cel serve list` (new TTL column, `permanent`, plus the server's directory and command), the dashboard's server rows (with directory and command) and `cel fleet` (`box.servers`, plus a `server` line under its workspace) show it with owner, port and memory.
- Registering and stopping a permanent server take the same authority: a person may act for any owner; an agent only for the alias its launch fixed (`CEL_INBOX_ME`, verified against the launch). Another agent, or one that shed `CEL_ROLE`, is refused. A server already registered is never re-registered to another owner. It may run anywhere; the record keeps its unit's `WorkingDirectory` and `ExecStart`.
- A permanent unit is matched by name: systemd recreating it keeps the registration, and adopting a pid that runs inside a user service registers that unit. A unit gone for 15 minutes (`CEL_SERVE_GONE_GRACE_SECONDS`), or a pid that exits, is dropped from the registry with one inbox note to its owner and never restarted.

### Changed
- `cel serve adopt` without `--port` records the port it saw the server listening on (was 0), and a unit named `x.service` is recorded as `x`.
- `cel serve list --json` (and so `cel fleet` and the dashboard) costs a constant number of processes whatever the number of servers: one jq over all records, one batched `systemctl --user show` for every unit, memory and pid start times read with builtins.
