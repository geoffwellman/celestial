### Fixed
- A subscription window whose reset has passed is no longer reported with its old utilisation anywhere. The steward kept sending `usage-pace` ("claude 5h: 97% now, ~97% at reset ...") hours after that reset because the past-reset check could only read a `...Z` time, not Anthropic's own `...T02:09:59.995970+00:00`, so every gateway or direct Claude reading counted as "no reset known" - never past, and never projected (its pace always equalled its use). One rule in `lib/quota.sh` (`_SUB_RESET_JQ`) now reads every reset spelling and turns a passed window into `reset: true` with no number; `cel quota`, `cel fleet`, the steward and the dashboard Usage card all read rows through it. `cel quota` and the card say `reset, no fresh reading` for such a window.
- A fresh read that fails (provider down or rate-limited) no longer erases a reset: the row stays `unreadable` and still lists the windows of the last reading that have reset since, as reset with no number. A window still running is not carried.
- The steward remembers the reset each subscription item quotes. Once it passes, the item comes down once - `<window> reset, no fresh reading` when no fresh reading has a number - and a fresh post-reset reading over the threshold raises it again at once instead of waiting out the four-hour repeat window. The 5h and 7d windows are handled the same way.
- `cel quota`'s window line no longer shifts a scope into the reset column when a window has no reset time.
