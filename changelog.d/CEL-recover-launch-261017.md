### Added
- `cel-fanout recover inspect|register|continue`: orchestrator-only canonical recovery of a worker whose launch was only partly recorded - a live agent in its pane, the right worktree and branch, and no ledger row (a `cel-fanout delegate` that died or timed out between `herdr agent start` and the ledger write, the 2026-10-17 W710 case). `register` validates the exact pane, shell, agent process generation, environment, model, branch and worktree against an explicit original coordinate and herdr's own `launch_pending`/idle report, refuses with zero mutation on any mismatch, a still-running original delegate, a held ledger lock or a conflicting row, and records one `unconfirmed` row with a `recovery` namespace (provenance `legacy-operator-attested`; original start time, task delivery, model success, session file, approval and head_source are listed as unproven, never invented). `continue` sends the spec prompt at most once, only to an agent herdr reports interactive_ready and not launch_pending, and moves the row to `running` (and the ticket to In Progress) only after the pane shows the agent took a turn; a crashed, errored or unevidenced submit is kept as debt and never resubmitted. herdr 0.9.1 has no call that completes or clears a pending launch, so a still-pending agent is refused with that upstream prerequisite named - no Enter, no pending reset, no second start. `release` and `collect` refuse an unsettled recovered row and `gc` keeps its worktree.

### Fixed
- `cel-fanout delegate` writes its ledger row BEFORE `herdr agent start` (state `unconfirmed`, `launch.phase` starting), so a delegate interrupted - or a herdr start that times out after the agent exists - can no longer leave a live agent with no row. A failed start is not rolled back: the row stays with `launch.phase` `start-failed` and says an agent may exist. After an accepted dispatch the row moves `unconfirmed` -> `running` as a recorded transition. Installed sessions keep the old CLI until this is deployed.
