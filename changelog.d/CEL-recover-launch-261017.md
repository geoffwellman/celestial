### Added
- `cel-fanout recover inspect|register|continue|abandon`: orchestrator-only registration of a worker whose launch was only partly recorded - a live agent in its pane, the right worktree and branch, and no ledger row (a `cel-fanout delegate` that died or timed out between `herdr agent start` and the ledger write, the 2026-10-17 W710 case). `register` validates the exact pane, shell, agent process generation, environment, the exact model and thinking-level launch arguments, branch, worktree, an unstarted pane (context zero, no turn) and herdr's `launch_pending`/idle report against an explicit original coordinate, refuses with zero mutation on any mismatch, a still-running original delegate, a held ledger lock or a conflicting row, and records one `unconfirmed` row with a `recovery` namespace (`legacy-operator-attested`; original start time, task delivery, model success, session file, approval and head_source are listed as unproven, never invented). `continue` sends the spec prompt at most once, only to an agent herdr reports interactive_ready and not launch_pending, and moves the row to `running` (and the ticket to In Progress) only after the pane shows the agent took a turn; a crashed, errored or unevidenced submit is kept as unresolved and never resubmitted. `abandon --reason` is the bounded way out of an unsettled row where no task was ever submitted (a submitted-but-unproven dispatch is refused and stays fenced until `continue` sees evidence): it records the reason and moves the row to `abandoned`, touching no agent, pane or worktree.
- **Not a full recovery - upstream blocked.** No supported completer was found in herdr 0.9.1's exposed surfaces (agent.start/prompt/wait/explain/rename, pane.report_agent/report_agent_session/clear_agent_authority/release_agent) - what the installed binary shows, not proof the capability cannot exist - and the only things that would change a pending launch (report-agent, release-agent, Enter) are forbidden here. A worker herdr still reports `launch_pending` can therefore be registered but not resumed; `continue` refuses and names the prerequisite: (1) a diagnostic reason why the launch is pending, (2) a supported way to complete it or mark the agent ready with no keystrokes or metadata forgery, (3) prompt-delivery receipt semantics. The tests' happy-path `continue` uses a fixture where herdr reports the agent ready, so it exercises this tool's logic only, not real herdr continuation.
- An `unconfirmed` row that may hold a live agent (a recovery row, or a delegate receipt at launch.phase starting/start-failed/started) counts toward the worker cap and is refused by `release`, `collect`, `land`, `review approved`, `request-review` and `handback`; `release --all` skips it and `gc` keeps its worktree.

### Fixed
- `cel-fanout delegate` writes its ledger row BEFORE `herdr agent start` (state `unconfirmed`, `launch.phase` starting), so a delegate interrupted - or a herdr start that times out after the agent exists - can no longer leave a live agent with no row. A failed start is not rolled back: the row stays with `launch.phase` `start-failed`, and `delegate --reuse` over an existing row marks it instead of replacing it, so a failed resume keeps its review verdict and PR. After an accepted dispatch the row moves `unconfirmed` -> `running` as a recorded transition. Installed sessions keep the old CLI until this is deployed.
- Behaviour change: a delegate row whose dispatch was never confirmed (`unconfirmed`, `launch.phase` `dispatch-unconfirmed`) is now uncertain delivery debt - a prompt may have been delivered. `collect`, `release` (including `--discard`), `land`, `review approved`, `request-review`, `handback`, `replace reserve/attach` (and a replacement child of such a source) refuse it, `release --all` skips it and `gc` keeps its worktree. It has no abandon path and no supported exit in this tool; the delegate warning no longer suggests a blind re-prompt.
