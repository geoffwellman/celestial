### Fixed
- Rex reviewer retirement reads Pi's stats line only in Pi's own shape: optional counters, then the context usage, from the line's first character. A two-line footer whose second line was an extension status with a usage-like token (`build running 40%/100`) used to pass unscanned; it is now `unknown_pi_footer`. Only the extension status line is scanned for busy words, so an idle reviewer on a model named `*-thinking` is still retired.
- `cel gc` and `cel solo land` no longer lose each other's updates to `~/.local/state/cel/gc-reviewer-retire.json` (and `gc-reviewer-unknown.json`): each read-modify-write holds an flock on a sidecar `.lock` file and writes through a private temp file in the same directory renamed into place.
- Every `unknown` answer of a targeted reviewer retirement is now counted, including the ones returned before the retirement ran (roster or registry unreadable, more than one matching reviewer, a reviewer with no alias, an invalid response), so `cel solo land`'s "tells <product>-orch if it keeps failing" always holds. Those that cannot name the reviewer are counted for the PR and end when its reviewer is retired.
- Retirement counts are keyed by pane, reviewer alias and PR. Each gc pass drops the counts of reviewers on neither the registry nor the roster (skipped when the registry cannot be read, the roster is empty, or rows produced no candidate), and a pane id that now carries another reviewer starts a fresh count instead of inheriting `reported`. Entries in the old format are dropped.
- `cel solo land`'s `Not landed` comment takes paths, `$HOME`, URLs carrying credentials, `*token`/`*secret`/`*password`/`*api_key` values (`access_token=`, `client_secret=`), an `Authorization` header's scheme and value, `Bearer`/`Basic` values and long hex or base64-like runs out of the forge's reason - the whole line, before it is cut to 300 characters - and posts the comment without the reason if it would fail the hygiene scan the squash body gets.
