### Changed
- Rex: a product's team is one Rex session group. `cel run reviewer` (Rex backend) and `cel run member` (when its lead runs in Rex) open the agent as an unfocused window labelled with its alias inside the product agent's own session - the team's `lead`, else `<product>-orch` - instead of a new session per reviewer. The host session is used only when proven like any managed agent (its receipt, live PID/start generation, and Rex reporting that PID in the receipt's terminal); otherwise the agent opens a session of its own as before and says so in one line. Receipts record `rex_scope` (`session`/`window`), `rex_window`, `rex_host` and a member's `team`; `cel sessions` lists them.
- Retirement works at window granularity: a window-scoped reviewer's native retirement and `cel team retire` of a Rex member close only that agent's window (`rex window close`), after proving it holds exactly the agent's one terminal running its exact runtime (or nothing, once exited); the product agent's session and its other windows are never closed, and a window someone added a terminal to is protected. `rex_agent_stop` closes only the agent's own terminal, scoped to its window.
- After a Rex server restart, reviewers and members stay held with the door that brings them back (now naming `cel team retire`/`cel team add` for members), which reopens them as windows in the resumed product agent's session.
- Team members may no longer run Rex terminal controls (`rex new|run|split|kill|send|send-key`, `rex window|block|session new|close|kill|destroy`): they share their lead's session.
