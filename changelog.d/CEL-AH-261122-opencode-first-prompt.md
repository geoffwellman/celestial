### Fixed
- `cel run --fresh --handoff` for OpenCode started an agent that could never work: the kickoff on the launch line makes the TUI create and prompt its session about a second after the launcher writes its private launch proof, before the celestial plugin's first 3 s observer tick reads that proof. The plugin ignored a session created while it had not yet read the proof, so the session was never bound: the kickoff failed with "Celestial OpenCode root is not bound", as did every later turn, and no inbox mail was delivered. The plugin now reads the written proof when the session is created and binds it; a session created while the proof is still absent stays unadopted, as before.
