### Fixed
- A Rex launch whose terminal never starts its runtime ("opened but has not started its runtime", "exited during startup") now closes the `--keep-open` terminal it opened. The close waits for the launch script to give up and checks that the terminal holds only that script. The launch then returns non-zero instead of dying, and a retry is admitted. A `--restart` that hits this prints the same "its Rex terminal was closed ... Bring it back with: cel run ..." recovery line as a relaunch that dies before admission. A terminal that cannot be closed keeps its pending markers, so a blind retry is still refused, and the restart says to close it first.
- The recovery line of a failed Rex restart never comes out as a bare `cel `. When no relaunch line was recorded, it names a hand restart instead (`cel run <role> --product ... --lane ... --workspace ... --session-backend rex`, plus the profile/model the agent ran on).
- A Rex launch of core that fails now makes `cel core` exit non-zero.
