### Fixed
- A gateway account whose token refresh the provider refused now reads as `needs login: cel gateway login <provider> - the gateway cannot refresh it (<gateway message>)`. Before this, it read `token stale - refreshed next time this account serves traffic` indefinitely, even though CLIProxyAPI had already tried the refresh and been refused (`invalid grant`). When the vault's token has expired, `cel quota` now makes one read-only loopback call, `GET /v0/management/auth-files`, using the existing management secret. That secret is never created by this call, never placed in argv, and only read when the file is private to the owner. The call returns the gateway's last refresh outcome for that file, and a refresh that failed in some other way is shown as `token stale - the gateway refresh is failing (...)`. Celestial still never refreshes a credential.
- A last-known window (the read failed) that was read more than `CEL_SUB_UNREAD_AFTER_H` hours ago (default 2) is now marked `unread: true` and is never forecast. The steward's `usage-pace` item and the dashboard Usage card no longer project from it. Instead, the item names the account with `not read since <time>: <reason and what to do> (last known 7d 73%, not forecast)`, and it stays open until a reading comes back. A last-known window at 100% still blocks and vetoes, as before.
