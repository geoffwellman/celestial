### Changed
- The steward's "unledgered preview/dev servers" report now goes out only when the SET of those servers changes, not daily to every product's agent. A server is known by its unit name, or a bare pid by its working directory and command name - never its pid, memory or age - so a dev server restarted in the same directory is the same server. A change is one message to root (the first registered workspace's): what is new, what is gone, and the full current list. An unchanged set sends nothing; a server that goes and comes back is new again. Each new server's line also goes to the agent whose directory it runs in: a repo checkout or solo worktree to the repo's PR owner (its lane, else its product's agent), a product directory to its agent, a lane's directory to the lane, anything else to its workspace's root. A send that fails is retried on the next tick. `cel serve adopt`, the dashboard and `cel fleet` list the unledgered servers as before.
