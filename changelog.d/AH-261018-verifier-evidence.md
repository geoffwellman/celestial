### Fixed
- `cel-verify` no longer deletes the full gate output. Every attempt (pass, fail, timeout, killed) keeps the complete output as a private artifact (`~/.local/state/cel/verify/<branch>/<head12>-<utc>-<pid>/gate.log`, 0700/0600, outside the worktree, never overwritten, indexed in `attempts.jsonl`); the verdict records `gate.artifact`, `output_sha256`, `output_bytes`, `attempt` and `head` next to the exact exit code. The 12-line tail remains the display text.
- `cel-fanout land` and `status` no longer collapse an explicit `gate: false` into "unknown": land says `verdict: false`, and status shows `FAIL` for a failed gate (jq `//` treats false as absent).
- The gate output streams straight into the artifact from the start, so no verifier crash can erase bytes already printed. A catchable termination of `cel-verify` (TERM, INT, HUP) stops the gate's group and records `no_verdict` ("cel-verify itself was terminated"), the index entry and `attempt.json` state `completed`. SIGKILL cannot be handled: no verdict or final index is written; the artifact keeps every byte printed and `attempt.json` still says `state: running` (the documented limit - never a faked verdict).
- `CEL_VERIFY_ARTIFACT_DIR` is refused (exit 4, before the gate runs) when it is inside the verified worktree or any git work tree, or is not owned by you with mode 0700.
