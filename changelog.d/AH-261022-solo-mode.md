### Added
- Solo mode: a product can be built by one agent instead of an orchestrator with workers. `mode: solo` on a `products[]` entry (or on the repo of an implicit product) makes `cel run orchestrator` start the solo agent; `cel run solo` does it for one launch. The solo agent keeps the product's directory, pane name and `<product>-orch` mailbox, launches with `CEL_ROLE=solo`, and may write, commit, push, open PRs, use its own worktrees and subagents, and start a reviewer for its own PR; the guard refuses fan-out verbs, starting other agents or panes (`herdr agent start`) and manual merges (`gh pr merge` in any spelling, `gh api .../merge`). Its policy block drops the worker, profile and scout lines.
- `cel mode [<product>] [solo|fleet] [--no-restart]` reads or switches a product's mode. The switch edits one line of `workspace.yaml` in place (through a symlink, keeping a missing final newline), verified as data before it is written, and refuses solo while fleet work is in flight. It restarts the product's own agent (`<product>-orch`, matched by name and directory) into the new role on the same session once it has been idle or done for two polls - never while working or blocked on an approval, never with `--force` - and leaves an already pending restart alone.

### Fixed
- The worker guard's refusals could be evaded by extra spaces, tabs, quotes, `--workspace`/`-C` before the verb, or a `cd x &&` chain. Worker and solo rules now share one normaliser that splits a line into the commands it would run and matches the verb at the start of each, so text that merely mentions a verb (`grep "cel-fanout land"`) is not refused.
- The YAML read cache keyed a symlinked file on the link, not its target, so edits to the target were not seen until the cache was cleared.
