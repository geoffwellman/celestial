### Fixed
- `cel solo land` and `cel-fanout land` now read a base branch's required checks from repository and organisation rulesets as well as classic branch protection, using the same rule as `forge_pr_checks`. Before, a branch gated only by a ruleset answered "Branch not protected", so the ruleset's required checks were ignored and `cel solo land` ran the local gate instead. A ruleset-required check must now be green on the PR head. The local gate runs only when neither classic protection nor any ruleset requires a check. If the rules cannot be read, or a rule requires checks without naming them (required workflows, code scanning, deployments), the land is refused.
- `cel inbox open --ranked` (triage) on a corrupt mailbox now fails with an error naming the file. Before, it showed nothing, as if no mail was waiting. In an `--all-workspaces` ranking, the other mailboxes are still ranked and the command exits non-zero.
- The steward's unread-mail sweep no longer treats a corrupt mailbox as having nothing actionable. It logs that the mailbox is corrupt and sends no reminder based on it.
- The Claude idle-mail watcher no longer fails its poll when the mailbox cannot be read. It wakes the session once for that mailbox so its own `cel inbox read` reports the corruption. Like any unread mail, the wake is retried only until Claude's transcript shows it arrived.
