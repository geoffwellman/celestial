### Fixed
- `cel forge pr close`, `pr ready` and `run rerun` check the caller's identity against its launch, as `cel team`'s writing verbs do: the nearest process above `cel` whose `/proc/<pid>/environ` carries `CEL_ROLE` must agree on `CEL_ROLE`, `CEL_PRODUCT`, `CEL_INBOX_ME`, `CEL_INBOX_WS` and `CEL_TEAM*`. A product agent that exports another product's `CEL_PRODUCT` (however indirectly) is refused before any write, and so is a role with no launch above it.
- No environment variable skips or redirects that check any more. `CEL_TESTING` without `CEL_PROC_DIR` used to skip it for `cel team` (and an indirected `export $X=1` got past the guard). Now the check always runs, and the test seams `CEL_PROC_DIR` (identity, inbox console liveness, pane launch env) and `CEL_FORGE_CURL` (where the forge token goes) are honoured only for a process under its own checkout's `tests/run.sh`, decided from the process's ancestry in `/proc`, which no variable can set. Outside it, `/proc` and the `curl` on `PATH` are used. The limit is documented (lib/common.sh `cel_under_suite`, docs/architecture.md): the seams are trusted for every process beneath that `tests/run.sh`, so agent code the suite runs can forge an identity or receive the forge token - accepted, since agents run as the owner and can read the token anyway.
- `tests/run.sh` refuses to start with `BASH_ENV` or `ENV` set (exit 2, no test runs), and the guard refuses an agent line that runs `tests/run.sh` while setting or exporting `BASH_ENV`, `ENV` or `PATH`, or with a `BASH_FUNC_` spelling, `export -f` or `declare -fx`.
- The guard refuses a line that runs `cel` while setting a variable whose name is an expansion (`export $X=1`, `declare -x "${X}=…"`, `eval "$X=1"`, `env "$X=1"`, `printf -v "$X"`, `read "$X"`) or declaring a nameref (`declare -n`), and one that hands cel's bash shell code: `BASH_ENV=`, `ENV=`, `SHELLOPTS=`, `BASHOPTS=`, a `BASH_FUNC_` spelling, `export -f` or `declare -fx`.
- `bin/cel` runs its checks in a clean process: unless the environ it started with carries no `BASH_ENV`, `SHELLOPTS`, `BASHOPTS` or exported function (and the shell is not interactive), it re-executes itself without them (and without `ENV`) before loading anything, so smuggled shell code - an exported `exit` that returns, a function that shadows the check - never reaches cel's checks. A BASH_ENV file still runs once, in the process that is replaced. The identity check also reads `/proc` with shell builtins only, so a `PATH` with other binaries first cannot feed it a forged environ.

### Changed
- The launch-environ check moved from `lib/team.sh` (`_team_launch_identity`) to the shared `lib/identity.sh` (`cel_launch_identity`); `cel team`'s behaviour and messages are unchanged.
