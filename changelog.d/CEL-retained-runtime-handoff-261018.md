### Added
- `cel-fanout handoff inspect|apply|status|hold` (orchestrator only): an admitted, replayable operation that moves an existing delegation's retained worktree to ONE replacement runtime on a named profile. `inspect` is read-only (plan, refusals, the exact apply line); `apply` is bound to the inspected pane, shell pid, agent pid + start generation, HEAD and a digest of every dirty/untracked byte plus private `.agent/` files, revalidates them (and idle + quiescence, no children/listeners/preview, no draft, no pending launch, a trustworthy herdr) immediately before mutating, and refuses with zero mutation otherwise. The operation record, ledger mark and a per-target lock are written before retirement; each phase is recorded before its call; a lost response or rerun continues the same operation (never a second stop, start or prompt); retirement, start and acceptance timeouts stay durable debt with an exact next action. The replacement starts in the same worktree with the profile's exact model/thinking and normal env/inbox/role, is verified, prompted once, and is `running` only after an assistant turn plus a successful tool call. Local-ahead and diverged dirty work is supported (classified with git, never reset/stashed/rebased/pushed). Cross-harness handoff is a context transfer, not a lossless resume; prior review approval is not carried over. `handoff hold --kind launch-unknown` records an unsettled launch (e.g. a `delegate --reuse` that timed out UNKNOWN) that fences retirement, restart, collect, release, land, handback and `recover abandon`.
- **Upstream blocked for retirement.** herdr 0.9.1's API schema has no process-only agent retirement. The exact missing call is `agent.stop` (`herdr agent stop <name>`: end one agent by name, release its name, keep the pane, shell and other processes). Until herdr ships it, `handoff` refuses at inspect and apply and names it; `pane.close`, `release_agent`, keystrokes, kills and alias renames are deliberately not used. A launch of unknown outcome needs a herdr launch receipt (outcome of `agent.start` by launch id, plus a supported cancel) to be settled. Installed sessions keep the old CLI until this is deployed.
- `handoff` session safety (fail closed): an unknown or missing recorded session REFUSES retirement (an archive named with `--preserved-export` is evidence only and never unlocks it); the last assistant message's tool calls must ALL have results (parallel calls checked by id; an unparseable tail is unsettled) - also for any resume file. `--resume-session FILE --resume-sha SHA` (pi targets only) is accepted only for the old runtime's OWN recorded session file by real path (symlinks, hardlinks, copies and archives are refused), with a header uuid and cwd equal to the worktree, bound by bytes; the replacement is started as `pi --session FILE` (argv adjacency verified). Only "launched on that file" is claimed. Otherwise UNAVAILABLE with zero mutation; the tool never copies, moves or symlinks sessions.
- `handoff` capability gate is the CONTRACT, not a method name: `agent.stop` must take the agent name AND `expected_pid` + `expected_start` (a generation fence); the stop call passes `--expected-pid/--expected-start`. This is this tool's stated requirement of the upstream call; herdr 0.9.1 has no agent.stop. An interrupted admission (record written, ledger not yet marked) is re-marked idempotently on replay. `handoff settle <id>` is the only exit from a hold and is UNAVAILABLE (zero mutation) until herdr offers a launch-receipt query; held rows keep occupying worker slots; closed rows cannot be held. Known limit: the per-target lock descriptor is inherited by short-lived herdr CLI children.
