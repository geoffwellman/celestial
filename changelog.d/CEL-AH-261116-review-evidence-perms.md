### Fixed
- A Rex reviewer launched on a box whose umask is 002 could never be retired: `tools/reviewers/retire.mjs` refuses evidence a group can write (`unsafe_evidence_permissions`), and Pi created the reviewer's native session 0664 (its role file was already 0600; `.cel/reviews/pr-<n>` was 0775 but is not what the check reads). Every `cel gc` sweep and `cel solo land` retried and refused. Review evidence is now private when it is created, whatever the umask: a reviewer's runtime starts under `umask 077` (Pi's session and task metadata, a QA agent's screenshots, anything it writes - so another user or container can no longer read them), `cel run reviewer` creates `<ws>/.cel/reviews/pr-<n>` and a QA agent's `qa-<focus>.shots` 0700, and `cel solo review --qa ... --evidence` copies into `.cel/qa-evidence/` 0700/0600. Evidence an earlier launch left group-writable is tightened (group/other bits off) by the next reviewer launch for that PR, or just before a real retirement attempt - the PR's `.cel/reviews` evidence, the checkout's `.pi/tasks` and the reviewer's own native session. Each path is opened one component at a time with `O_NOFOLLOW` and its fd re-checked, and only a directory or single-link regular file this user owns is changed; each change is logged. A dry run changes nothing, and the retirement check is unchanged: anything left (another user's, a symlink, a hard link) is still refused.
