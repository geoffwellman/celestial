### Fixed
- `cel gateway rotate-key --status` now bases an INTERRUPTED rotation on what `config.yaml` actually accepts, compared with the key files, instead of only on which files exist. It names the keys accepted (the current key, `api-key.next`, a key in no key file), the rotation files left over, and the verb that was cut short when that can be told. It also gives the matching fix: `--abort`, or `--abort` again, which also stops accepting a key in no key file (as `cel gateway refresh` does). It no longer claims an `api-key.next` is still accepted after an `--abort` was cut short. A test now also pins the `CEL_GATEWAY_ROTATE_CRASH_AFTER` test seam as inert outside the suite.
