### Fixed
- A new node release that moved mise's `lts` alias left npm-global agents (pi) as dead mise shims: `command -v pi` succeeded and `pi` printed `No version is set for shim: pi`. `cel setup` kept such an agent as "retained", and `cel update` ran its updater through the dead shim.
  - A dead shim is no longer a working agent. `cel setup` and `cel update` reinstall it under the active node with the agent's own installer, at the newer of its pin and the release the previous node still holds. `cel update` does this before it runs the agent's updater. A working agent is still retained, whatever its release. `agents.yaml` gains `npm_package` (pi: `@earendil-works/pi-coding-agent`) to name the package.
  - `cel update` now also runs the `npm_tools` step (REA), so a tool missing from the active node's global root is installed there at its verified pin. A tool at or above the pin is kept.
  - Node is not pinned per tool. mise's `npm:` backend or a fixed node path would write the mise config that `cel update` leaves alone, bypass the `npm_tools` integrity check, and split pi from `pi update --self`, which installs into the active node's prefix.
- `cel doctor` names every dead mise shim. For an agent or a plane npm tool it is a failure with the fix (`cel setup --agents <agent>` or `cel setup`) and the release the old node holds. For any other tool, such as graphite's `gt` and `graphite`, it is a warning with the exact `npm install -g <package>@<version>`. An agent whose `--version` exits non-zero is also a failure; doctor no longer shows it as installed.
- `cel run` and `cel core` (including `--restart`) refuse a runtime whose bin is a dead mise shim. They refuse before writing a role file, claiming the session, stopping the agent or asking Rex for anything, and they name the fix. Previously a `--restart` closed the agent's terminal and then watched its relaunch die at exec.
- The first session claim of a launch no longer prints `<state>/session-claims/<key>: No such file or directory`. The claim file is absent on a first claim, and bash reported the redirect before `2>/dev/null` applied, so the message read as a missing session-claims directory.
- OMP launched at its default root (`~/.omp/agent`) no longer carries `PI_CODING_AGENT_DIR=~/.omp/agent`, and any inherited value is removed. The variable is OMP's default anyway, and every child OMP ran inherited it, including its bash tool and MCP servers. As a result a plain `pi` or `rea setup --client pi` run from core's shell used OMP's root as pi's. A custom `CEL_OMP_AGENT_DIR` is still passed by value, because OMP has no flag for it. Pi launches are unchanged.
