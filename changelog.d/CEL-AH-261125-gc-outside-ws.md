### Fixed
- `cel gc` now covers every repo every registered workspace declares, by the real path of its clone (a `repos/<name>` symlink to a clone outside the workspace is followed), and every linked worktree `git worktree list` records for it wherever it lives - beside the clone, in `/tmp`, anywhere. Before, it only looked at herdr worktrees and solo worktrees under the workspace, so a repo cloned outside `~/ws` piled up worktrees nothing removed. Those worktrees go under the solo rules unchanged: a merged or closed PR for the exact head, clean and landed, no live process (the zombie, unreadable-state and Samba rules included), no agent.
- In every pass, `cel gc` never removes anything under `~/orca/workspaces` (kept as `owner`) or a follow-main `local-*` tree (`follow-main owned`). It keeps as `claimed` a worktree that contains the owner root, another worktree, a clone, a workspace or its registered `repos/<name>`, or the review checkouts (ignored files are not "dirty", so a plain remove would take them); one that is a registered checkout; and one git has locked. It keeps a detached worktree as `detached`. A repo worktree with a pane or agent in it is `claimed` too, with every path compared as given and resolved; an unreadable pane list claims them all.
- Worktree records whose directory is gone are pruned with `git worktree prune --expire 7.days.ago` (a dry run names them). A record whose parent directory is also missing (an unmounted disk or share, a dangling symlink) is kept as `parent-missing`, and an owner's as `owner`. Prune clears every due record of a clone at once, so a due record of either kind keeps all of that clone's records (as `stale`), as does a record younger than the grace.
- `cel gc` prints one line per registered repo with worktrees - total, removed (or would be), stale records pruned, and kept by reason - and `cel doctor` shows the same lines from the last sweep.
- A checkout of a clone outside every workspace is asked about with its registering workspace's GitHub account; a clone registered by workspaces declaring different accounts is not asked about at all (its trees are kept).
