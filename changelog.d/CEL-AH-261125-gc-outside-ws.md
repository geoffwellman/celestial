### Fixed
- `cel gc` now covers every repo every registered workspace declares, by the real path of its clone (a `repos/<name>` symlink to a clone outside the workspace is followed), and every linked worktree `git worktree list` records for it wherever it lives - beside the clone, in `/tmp`, anywhere. Before, it only looked at herdr worktrees and solo worktrees under the workspace, so a repo cloned outside `~/ws` piled up worktrees nothing removed. Those worktrees go under the solo rules unchanged: a merged or closed PR for the exact head, clean and landed, no live process (the zombie, unreadable-state and Samba rules included), no agent. Never removed, by any pass: anything under `~/orca/workspaces` (kept as `owner`) and follow-main `local-*` trees (kept as `follow-main owned`); and a repo worktree something else claims - locked, a workspace's registered `repos/<name>` checkout, or with a pane or agent in it - is kept as `claimed`. A detached repo worktree is kept as `detached`.
- Worktree records whose directory is gone are pruned (`git worktree prune`; a dry run names them). Prune clears every stale record of a clone at once, so an owner's stale record keeps all of that clone's (as `stale`).
- `cel gc` prints one line per registered repo with worktrees - total, removed (or would be), stale records pruned, and kept by reason - and `cel doctor` shows the same lines from the last sweep.
- A checkout of a clone outside every workspace is asked about with its registering workspace's GitHub account.
