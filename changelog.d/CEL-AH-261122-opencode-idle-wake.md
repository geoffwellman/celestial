### Fixed
- An OpenCode agent left idle for an hour stopped waking for inbox mail. OpenCode 2.2.5 unloads a location's services after 60 minutes without session activity and boots them again only on the next request; the celestial plugin, whose observer delivers idle mail, was unloaded with them, so mail waited until the owner typed or the agent was relaunched (a product orchestrator on 22 Nov: unloaded at 01:50, root's 02:28 mail read only by the 02:46 relaunch). The guarded launcher (`tools/opencode/launch.mjs`) now hands its private server the validated scoped config with `experimental.location_idle_timeout: false`, so the agent's location stays loaded for the server's life. Running OpenCode agents keep the old behaviour until relaunched.
