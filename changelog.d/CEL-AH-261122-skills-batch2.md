### Added
- Seven more skills for every agent, vendored into `core/skills/` and linked into claude, omp, pi, codex and opencode: `mcp-builder`, `webapp-testing` and `anthropic-skill-creator` (anthropics/skills; upstream `skill-creator`, renamed because Codex bundles a system skill of that name) and `create-mcp-app`, `add-app-to-server`, `convert-web-app` and `migrate-oai-app` (modelcontextprotocol/ext-apps).
- Workspace-scoped skill sets: a `vendored-skills.yaml` entry with `set: <name>` lives in `core/workspace-skills/` and reaches only the agents of workspaces whose `workspace.yaml` lists that set in `skill_sets:`. `cel ws sync` (and so `cel update`) links them into `<workspace>/.cel/skills` and removes undeclared ones, writing nothing into a repo; every `cel run` launch for the workspace names that directory (agents.yaml `workspace_skills`: claude `--add-dir`, omp `--plugin-dir`, pi `--skill`, OpenCode `OPENCODE_CONFIG`). Codex links them disabled by resolved path in a marked `config.toml` block (`vendor.py codex-config`, which leaves a file it cannot edit with certainty alone and gives codex none of them) and a launch enables its workspace's with `-c skills.config=[...]`. Reviewers get their workspace's too.
- The `cloudflare` set (`workers-best-practices`, `durable-objects`, `wrangler`, `agents-sdk`, `workers-profiling`, `web-perf`) and the `expo` set (`expo-router`, `expo-ui`, `expo-native-ui`, `expo-animation`, `expo-dev-client`, `expo-upgrade`, `eas-workflows`, `eas-app-stores`).
- Skills whose upstream text has an agent deploy, publish, submit to an app store, spend money or run paid builds/generation (`mcp-builder`, `anthropic-skill-creator`, `workers-best-practices`, `durable-objects`, `wrangler`, `agents-sdk`, `workers-profiling`, `expo-native-ui`, `expo-dev-client`, `eas-workflows`, `eas-app-stores`) open with a recorded patch note naming the commands that, under celestial rules, wait for the owner's approval.
- No vendored skill pre-approves shell commands: `vendor.py` refuses a `Bash(...)` `allowed-tools` entry, and the patches drop upstream's from `eas-workflows` (`node` and every `eas-cli` command) and `expo-ui` (a `node *...` pattern that also admits `node -e`).
- hygiene: `BY-4` (the SPDX `CC-BY-4.0` licence id in upstream licence text) is a standard token, not a ticket.
