### Added
- `cel forge run list <repo> [--branch b] [--sha <head>] [--limit N]`, `cel forge run view <repo> <run-id>` (the run and its jobs) and `cel forge run logs <repo> <job-id> [--tail N] [--raw]`: read-only CI for every role on Forgejo (Actions over its API, no web login and no token in the agent's hands) and GitHub (`gh run`). Ids are the API's; the web UI's run number is shown beside it as `web #N`, and `--sha` lists a commit's runs with each one's job ids. `view` and `logs` also take a run's or job's web page, mapped by Forgejo's own `html_url` or refused with the `--sha` hint. Run and job states are success · failure · cancelled · skipped · running · queued (Forgejo's `status: failure` with a null `conclusion` is a failure); `logs` drops per-line timestamps (and GitHub's job/step columns) unless `--raw`, and on GitHub shows the job's failed steps.
- `cel forge run rerun <repo> <job-id>` (Forgejo `POST /actions/jobs/<id>/rerun`, GitHub `gh run rerun --job`): the job runs again on the same head, so an approval of that head stands.
- `cel forge pr close <repo>#<n> [--comment-file f]` (the comment posted first, the branch never deleted) and `cel forge pr ready <repo>#<n>` (Forgejo: the `WIP:` / `[WIP]` title prefix removed; GitHub: `gh pr ready`; a no-op on a PR that is not a draft), so a Forgejo PR opened as a draft can be landed.
- Who may close, ready or rerun: the owner - a shell with no Celestial agent mark at all (no launch variable, set or emptied, and no agent runtime among its ancestors) - or the product's own agent (`CEL_ROLE` solo or orchestrator) on its OWN product's repos only, and on a PR only one its workspace account authored or a migrated Forgejo PR (author `Ghost`). An empty or unset `CEL_ROLE` is never the owner. Core, root, team members and reviewers are refused. Every agent and the owner act as the one workspace account, so authorship cannot tell an agent's PR from the owner's own on the same product: that is the documented limit.

### Changed
- The box-wide budget counts helpers only: `budget.max_live_agents` (default 8) now holds reviewers, team members and other launched agents. Product agents (`*-orch`, solo lanes) and core/root are shown by `cel budget` but never counted, so a box running ten products no longer refuses every reviewer. `budget.max_team_members` (4) and the memory floor are unchanged; `cel budget --json` adds `live.helpers`.
- The guard refuses every agent that sources `lib/forge.sh` or calls its `_forge_*`/`forge_*` functions (also inside `bash -c`, `$(...)`, an `eval`, or through a variable holding the name), and any line that runs `cel forge` while setting, emptying or unsetting a `CEL_*` variable (`VAR=`, `env -u`, `env -i`, `unset`, `export`). Both are tripwires like the rest of the guard, not a sandbox: a script file still runs.
- The Forgejo test fixtures are re-recorded GET-only from Forgejo 17.0.1 and anonymised (tests/fixtures/forge/forgejo/PROVENANCE says per file what was recorded and what is still spec-derived); new recorded fixtures cover migrated PRs and reviews (author Ghost, no commit), Actions statuses, runs, jobs and a job log, and GitHub's `gh run list|view` and a failed job's log.

### Fixed
- Forgejo `mergeable: false` reads `unknown`, never `conflicting`: Forgejo also answers false before it has (re)computed a PR - recorded live on a clean fast-forward - and its API has no field that proves a conflict. `cel solo land` and the ready-to-land list do not treat unknown as a conflict.
- A Forgejo Actions commit status's site-relative `target_url` is made absolute in `cel forge pr checks`.
- Forgejo list pages are passed to jq on stdin: a page of Actions runs outgrew the kernel's argument limit and `run list` printed nothing.
