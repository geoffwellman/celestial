### Fixed
- When a gateway token has expired, `cel quota` asks the gateway why. That management read (`GET /v0/management/auth-files`) is now cached for `CEL_SUB_TTL` (60 s) in `gateway-states.json` in the subscription cache directory. The file is written whole with mode 0600 and records which gateway URL answered. A failed read is cached too, so a gateway that is down costs one five-second timeout a minute instead of one per steward tick and per `cel quota`.
- The management secret is now sent only to a loopback gateway URL (`127.0.0.1`, `::1` or `localhost`, over http or https, with no user info). Any other `CEL_CPA_GATEWAY_URL` is refused before the key file is read.
- A last-known window at 100% that is also `unread` now stays at risk. It is never projected: `quota_at_risk` gives it a `say` of `100% spent (last known, not read since <time>)`, the steward's usage-pace item uses that text, and the dashboard Usage card still flags it. In the steward's "not read since" line, a spent window now reads `7d 100% spent (last known, not read since <time>)` and any other window reads `7d 73% not forecast`.
