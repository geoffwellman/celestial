### Fixed
- The Forgejo token could be handed to a binary the caller chose: `_forge_fj` piped it to whatever `curl` came first on `PATH`, so an agent that prepended a directory with a fake `curl` captured it with any read (`cel forge pr view`). Every forge operation (`cel forge`, `cel solo land`, the reviewer's PR facts, the steward) and every `cel team` verb now runs on a fixed tool path - the system directories, then the user's `~/.local/bin` with the home taken from `/etc/passwd`, never the caller's `PATH`. The token goes only to the system's `curl`, `jq` must be the system's (`cel forge` refuses otherwise), and a planted `jq` or `yq` can no longer flip an authorisation. A binary installed only in `~/.local/bin` (here `yq`, sometimes `gh`) cannot be told from one planted over it; that is the least-bad rule left.
- Every `gh` call runs the box's `gh` (`cel_gh_bin`: system directories, then `~/.local/bin`) on the tool path (`cel_gh_run`, with `GH_PAGER=cat`): `ws_gh` (with a workspace's token in `GH_TOKEN`) and the plain calls in `lib/afk.sh`, `lib/release.sh` and `lib/gc.sh`. gh starts git and a pager through `PATH`, and they inherit `GH_TOKEN`, so a git planted first on the caller's `PATH` is no longer handed the token. The gh test stubs (`CEL_WS_GH_BIN`, fed from `CEL_FORGE_GH`, `GH` or `CEL_AFK_GH`) are honoured only under the checkout's own test suite, like `CEL_PROC_DIR` and `CEL_FORGE_CURL`. A `gh` that lives only in a mise, Homebrew or cargo directory is now refused, loudly (gc reads that as unknown and keeps what it would have closed).
- `tools/reviewers/retire.mjs` no longer reads `CEL_WS_GH_BIN` from its environment, and no longer runs gh on the caller's `PATH`: lib/reviewer-retirement.sh resolves the gh and the tool path by the same rules and passes both as arguments; without them the retirement refuses to ask GitHub.
