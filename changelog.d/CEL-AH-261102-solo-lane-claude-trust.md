### Fixed
- `cel run solo --lane <name>` on Claude Code no longer stops at Claude's folder-trust prompt for the new lane directory, whose default answer ("No, exit") let any queued keystroke end the lane. Before anything starts, the launch records trust exactly where Claude Code reads it (`projects[<lane dir>].hasTrustDialogAccepted` in `${CLAUDE_CONFIG_DIR:-$HOME}/.claude.json`), for that directory only, under Claude's own `<file>.lock` and by atomic rename, leaving the rest of the file unchanged. A held lock or a file that is not a JSON object launches nothing.
- A brief sent to a Claude lane before its first launch now reaches it. A fresh Claude lane starts with a first turn, so the UserPromptSubmit inbox hook delivers the mail that is waiting; previously no turn was submitted and the lane reported it had no goal. Resumed sessions and other runtimes are unchanged. The lane's role text now also names its mailbox as a source of its goal.
