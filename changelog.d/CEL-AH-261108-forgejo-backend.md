### Added
- A Forgejo backend for every `lib/forge.sh` operation (view, list, checks, reviews, merge, current account) over Forgejo's REST API, normalised into the same shapes as GitHub's, plus `forge_pr_create` on both providers. The token lives in `~/.config/cel/forge/<host>.token` (mode 600; a missing or group/world-readable file is refused by name), goes only to that host, and reaches curl on stdin - never in argv. List endpoints are read page by page. Required checks come from the base's branch protection rule (exact, else matching globs); a branch reads as unprotected only on Forgejo's own 404 with no matching glob, and as unknown on any other error. A merge re-reads the head, refuses a moved one, and squashes exactly the expected head.
- `cel forge`: `repo`, `whoami`, `pr view|checks|reviews|list` (`--json` for the normalised value) and `pr create`, on GitHub or Forgejo. Opening a PR follows the workspace's ready/draft policy (Forgejo's draft is a `WIP:` title prefix). The guard refuses `cel forge pr create` to orchestrators and core.
- The guard refuses a forge changed by hand to orchestrators, root, core, workers and solo agents: curl at a Forgejo or GitHub API with a body or a non-GET method in any spelling (`-d@x`, `-dX`, `--data-*`, `-F`/`--form`, `-T`/`--upload-file`, `--json`, `-X M`/`-XM`/`-sXM`/`--request[=]M`, `-K`/`--config`), `tea api` with anything but a plain GET, and tea's write verbs with its global flags before them. It refuses reading, copying or writing the forge token (`~/.config/cel/forge`) to every role, by shell and by the native read and edit tools.
- A repo's `host:` may be written `http://<host>` for a forge served over plain HTTP only. Such a host receives the API token unencrypted on every request - use it only on a trusted LAN; every operation on it says so on stderr.
- `CEL_FORGE_CURL` (the Forgejo backend's curl stub seam) is honoured only under `CEL_TESTING`.

### Changed
- `cel solo land`, `cel solo review` and the reviewer's PR facts (`cel run reviewer`) speak to the PR's forge through `lib/forge.sh`, so a Forgejo repo reviews and lands end to end: verdict at the exact head, required checks or the local gate on an unprotected base, merge pinned to the head. The local gate now also fetches the PR's `refs/pull/<n>/head` from the forge and refuses unless it is the head the gate ran on.
- The reviewer brief and the reviewer and solo roles use `cel forge` rather than `gh` to read a PR.
- `land_ci_gate` (shared by `cel solo land` and `cel-fanout land`) is provider-neutral: it takes the PR's repo and `{number, head_sha, base_ref}` and reads the base's required checks and the head's latest check runs from one `forge_pr_checks` answer, on GitHub or Forgejo. A required check counts only when its latest run on the head succeeded (an earlier green run of a re-run that failed no longer counts), and a head that moved since it was read decides nothing.
- The steward's list of solo PRs ready to land (`solo_ready_prs`) reads every repo through `lib/forge.sh`, so Forgejo repos are listed by the same rules instead of being skipped.
